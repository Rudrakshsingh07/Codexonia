Quick start

Open the Submit Code page, edit the sample or paste your own Java, and press Run. The backend compiles the submission, starts it inside a hardened Docker sandbox, and records the execution with the Java Debug Interface.

  1. The main class is detected from the submitted files.
  2. The program runs under JDI, bounded by the sandbox limits below.
  3. The runner returns a versioned JSON trace with sources, stdout, and events.
  4. The browser receives the trace; no program is re-executed during playback.

What gets traced

Trace schema v1 has three event types. They are deliberately small: each event is an observation, not a rendered frame. Scene state is reconstructed from the ordered event stream.

EventMeaningUseful fields
METHOD_CALL A method is entered. class, method, args, line
ASSIGNMENT A local variable receives a value. var, old, new, line
METHOD_RETURN A method returns to its caller. class, method, ret, line

Every event also carries seq, file, and the source line. The sequence number is the stable ordering key used by playback.

Reading a trace

A trace is a time-ordered list, not a snapshot. To answer “what was true at step 12?”, replay the first twelve events in order and apply their effects:

  1. Stack: push on METHOD_CALL, pop on METHOD_RETURN.
  2. Variables: set the named local on ASSIGNMENT.
  3. Source position: use the event's file and line.
  4. Stdout: reveal the output produced up to that point.

Step backward

Do not run the program again. Rebuild the earlier state from the trace, or jump to a cached keyframe.

Step forward

Apply the next event to the current state. The event is the only source of change.

Sandbox limits

The defaults below are enforced by LimitPolicy. A limit hit is a classified outcome, not a silent truncation. The student sees the reason.

ResourceDefault
Memory512 MB
CPU1.0 core
Processes64
Wall-clock timeout30 seconds
Trace events20,000
Stdout / stderr64 KB each
Source size256 KB
Source files16
Sandbox tmpfs32 MB

The container runs with no network, a read-only root filesystem, all Linux capabilities dropped, and a non-root user. The host JVM never executes student code in-process.

Deterministic audio

Sound is derived from the event signature, not from a persisted lookup table. Codexonia uses FNV-1a 32-bit over the ASCII signature, then slices the unsigned hash into pitch, timbre, and duration:

  • Pitch: low bits select one of seven A-minor pentatonic notes.
  • Timbre: middle bits select sine, triangle, square, or sawtooth.
  • Duration: high bits select 150, 200, 250, or 300 ms.

The same signature always produces the same tone in every implementation. The shared contract lives in test-vectors.json and must match byte-for-byte. You can query the mapping directly: 

GET /hash?input=swap

HTTP API

Run a submission

POST /api/run accepts either a single source string or a files array.

POST /api/run · multi-file 
{
  "files": [
    {
      "fileName": "Sample.java",
      "source": "public class Sample { ... }",
      "isMainFile": true
    }
  ]
}

A successful response is a trace JSON object with schema_version, status, sources, stdout, event_count, and events. Validation failures, compile errors, timeouts, output caps, and runtime errors use classified status values.

Hash and tone mapping

GET /hash?input=<signature> returns the deterministic signature → hash → tone mapping. It is useful for testing cross-language implementations.

Troubleshooting

What you seeWhat it means
COMPILE_ERRORThe Java source did not compile. Read the compiler message shown in the run panel.
NO_MAIN_METHODNo class with public static void main(String[]) was found.
TIMEOUTThe program exceeded the wall-clock limit. Look for an unbounded loop or blocking call.
EVENT_CAPThe trace reached 20,000 events. Reduce the amount of work in the sample.
OUTPUT_CAPStdout or stderr exceeded 64 KB. Print less, or summarize inside the program.
Sandbox image missingRun ./run.sh once to build codexonia-sandbox:latest.
