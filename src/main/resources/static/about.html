About the project

A flight recorder for Java.

Codexonia exists for the moment a program stops being obvious. It records what the JVM actually did, preserves the order, and gives that evidence back as something a student can inspect without a debugger setup.

school Built for CS students code Java + Spring Boot science Course project · v2.0

Why this exists

Static code shows what could happen. A debugger shows what is happening, but only while you are sitting in front of it. Codexonia keeps the run: the calls, the assignments, the returns, and the output, all in one ordered trace that can be replayed later.

The product is deliberately narrow. It is not an IDE, a grader, or a general-purpose visual programming tool. It is a way to look at a working Java program and ask: where did this value come from?

Design principles

Every design decision follows from the fact that a trace is evidence. If the interface invents state, the evidence is gone.

fact_check

Evidence over narration

The player reads from recorded events. It does not guess what the program probably did.

graphic_eq

Deterministic by construction

A tone is derived from an event signature with a fixed hash. The same event always sounds the same.

shield_lock

Ephemeral by default

No accounts, no saved student database. A submission exists to produce a run, then it is gone.

open_in_browser

Link-and-go

No JDK install, no desktop client, no local setup. The browser is the delivery surface.
